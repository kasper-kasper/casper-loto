## Размер и лишние файлы

До подготовки коммитов первой публикации история содержала **393 коммита**.
Адрес выбранного закрытого репозитория: `https://github.com/kasper-kasper/casper-loto.git`.

Рабочий набор файлов, которые могли бы попасть в будущие коммиты,
занимает примерно **60 MiB**. Это исходники и изображения; размер всей папки
на диске не равен размеру публикации. Упакованная Git-история занимает
около **439 MiB**; первое клонирование с полной историей будет больше
рабочего набора.

- Найдена `output/` с посторонними документами и результатами их обработки:
  добавлены исключения из Git и Docker. Файлы сохранены.
- Готовые MP4 в `design/reels/casper-free-v1/out/` уже исключены из Git.
  Видео нет ни в текущем наборе отправляемых файлов, ни среди путей
  достижимой истории.
- `.venv/`, `.tools/`, `node_modules/`, кэши, резервные копии, дампы,
  приватный архив и настоящая `.env` остаются локальными.
- `design/reels/` содержит исходники отдельного ролика, включая музыку
  и изображения, примерно 9 MB. Это материалы для его дальнейшего редактирования.
- `archive/reference/` содержит около 21 MB исторических исходников
  и дизайн-исследований. Они не участвуют в production-сборке; сохранять
  их в репозитории допустимо. Удаление всего архива не требуется.
- Файлов более 50 MiB в проверенном рабочем наборе и достижимой истории нет.
- Временные объекты Git не удалялись вручную. `git fsck --connectivity-only
  --no-dangling` прошёл: недостающих достижимых объектов не обнаружено.

## Секреты и права на материалы

Заново проверены **5 705 достижимых Git blobs** и **839 файлов** рабочего набора
на момент запуска сканирования: поиск точных действующих секретов из текущей
`.env` без вывода значений, форматов GitHub/Telegram-токенов и приватных ключей.

Совпадений действующих секретов и кандидатов известных форматов не найдено.
В проверенных исторических путях нет настоящих `.env`, приватных
`.pem`/`.key`, дампов или SQLite-баз.

Это автоматическая проверка конкретных форматов и действующих значений.
Перед публичным открытием ещё нужен просмотр операционных документов
и исторических изображений на лишние личные сведения и прав на материалы.
Этот отчёт не является независимым аудитом безопасности или лицензий.

## Проверки кода и сборки

- Ruff, Ruff format и MyPy прошли.
- В исходной локальной Python-среде найдена версия `cryptography` вне
  `uv.lock`. Работающая среда не менялась: создана отдельная чистая среда
  через `uv sync --locked --extra dev`. В ней проверка runtime lock прошла:
  **67 дистрибутивов** соответствуют lockfile.
- В чистой Python-среде Ruff, форматирование и MyPy тоже прошли.
- Первый backend-запуск: 880 прошли, два упали из-за отсутствующего
  `ruleset_code` в тестовых объектах. Дополнены только два тестовых объекта,
  финансовое поведение приложения не менялось.
- Повторный запуск: **882 прошли, 68 пропущены** без специальной PostgreSQL-среды.
- Чистые клиентские проверки из npm lockfiles: Mini App — **251 тест**,
  админка — **68 тестов**; typecheck, lint и build обоих клиентов прошли,
  source/artifact hashes подтверждены.
- Vite выдал предупреждение о размере одного из чанков Mini App:
  это предупреждение оптимизации, сборка успешна.
- Создан отдельный временный PostgreSQL 16 для оставшихся сценариев.
  Миграции чистой базы до `0067` прошли, `alembic check` расхождений не нашёл.
  Полный backend-набор в чистой Python-среде с PostgreSQL: **949 прошли,
  один пропущен** (символические ссылки Windows, требуется Linux CI).
  Временный контейнер после проверки остановлен и удалён штатным `--rm`;
  существующий контейнер локального просмотра не менялся.
- Исправлен пробел CI: workflow теперь создаёт отдельную тестовую базу
  и задаёт `ACHIEVEMENT_TEST_DATABASE_URL`, чтобы PostgreSQL-тесты достижений
  не пропускались молча. YAML разобран, теги `v7` используемых GitHub Actions
  проверены через официальный GitHub API и существуют.
- Результат проверки Linux доступен в
  [GitHub Actions](https://github.com/kasper-kasper/casper-loto/actions).
  Windows-проверка символических ссылок недоступна; её должен подтвердить Linux CI.

## Что осталось перед открытой публикацией

1. Посмотреть английский и русский тексты уже на закрытом GitHub.
2. Отдельно выбрать и оформить лицензию с учётом сторонних материалов.
3. Перед открытием просмотреть личные/операционные сведения и права на материалы.
4. Проверить Linux Actions и отображение изображений на самом GitHub.
5. Отдельным решением владельца открыть репозиторий всем, когда он будет готов.

Эта работа меняет документацию, тестовые объекты и подготовку CI.
Игровой код, правила, деньги, схема данных и работающий VPS не менялись.
