# Шаг 5: сборки, выпуск и история — 14 октября 2026

Область работы: backend, бот, Telegram Mini App и Admin. Отдельная Web-версия
сохранена локально и исключена из проверок клиентов, Docker-контекста и выпуска.

## Изменения

- Backend устанавливает зависимости строго из `uv.lock`. Зафиксирован инструмент
  uv и сборщик setuptools; добавлена отсутствовавшая в lock-файле уже используемая
  Pillow. Сборка сверяет реальные установленные версии и записывает манифест.
  Системные пакеты и базовые Docker-образы пока не закреплены digest: это не
  обещание побитовой воспроизводимости всей операционной системы.
- Mini App и Admin собираются в новых временных каталогах через `npm ci`, без
  прежних `node_modules` и `dist`. Каждый выпуск содержит хеши исходников и ресурсов.
  `--reuse-built` отклоняет артефакты после изменения исходников/файлов.
  Устранена зависимость теста Mini App от исходников соседних клиентов.
- На VPS сначала формируется точный проверенный каталог кандидата и отдельные
  теги образов. Он не содержит оставшиеся на сервере старые исходники. Рабочие
  теги переключаются после интеграционных проверок. Backend-only выпуск сохраняет
  ресурсы действующего gateway. Для открытых вкладок сохраняются два предыдущих
  набора проверенных JS/CSS; бессрочное сохранение всех версий не требуется.
- Вся публикация удерживает общую блокировку операций. Перед заменой сохраняются
  дамп БД, исходники/ресурсы и образы отката; диагностические логи сохраняются
  перед пересозданием API/bot. Сроки хранения обслуживает один существующий
  `server_maintenance.py`. Удаляются только собственные временные файлы выпуска.
- Миграции выполняет выбранный новый образ, в том числе при выпуске только bot.
  После неудачной миграции старые workers возобновляются автоматически лишь при
  неизменной схеме. При частичном изменении схемы требуется разбор восстановления.
- Новый пустой PostgreSQL проходит историческую цепочку через отдельный безопасный
  bootstrap: только нулевые счета и исторические предпосылки перед миграциями.
  Существующая бизнес-история запрещает этот bootstrap. Повтор миграции индексов
  переживает частичное выполнение и восстанавливает собственный невалидный индекс.
- История Mini App использует курсор с привязкой к игроку и фильтрам, устойчивый
  порядок и загрузку полных данных только выбранной страницы. Число билетов в группе
  считается по всем подходящим билетам тиража, а не только текущей странице.
  Статистика любимых чисел агрегируется в SQL: профиль получает семь чисел вместо
  всех комбинаций игрока. Старый offset поддерживается для совместимости.
- Во время догрузки уже показанная история остаётся видимой. Повторное нажатие
  не запускает второй запрос, ответ прежнего фильтра не меняет текущий список.
- Неверная комбинация избранного возвращает HTTP 422 вместо 500.

## Проверки

Регрессии охватывают курсоры, изоляцию файлов выпуска и смену фильтра во время
догрузки. Реальные HTTP/SQL проверки используют только синтетические записи
во временной БД: подпись Telegram, Admin-вход/мониторинг, шесть видов покупки,
повтор, чек, отмена, cutoff, избранное, смешанная история, чужие чеки и курсоры.
Проверяется неизменность строк истории после чтения. Реальных тестовых покупок
и тестовых отправок Telegram в production нет.

Добавлен `.github/workflows/check.yml` с PostgreSQL, Python 3.12, lock-файлами,
серверными регрессиями и чистыми сборками двух действующих клиентов. Это готовый
workflow; GitHub Actions здесь не запускался, удалённый Git remote не настроен.

Первый выпуск 3a93bc1 опубликован 14 октября в 06:14 МСК. Последующий API-only
выпуск был прерван: исходники и образ остались в кандидате; защита некорректного
UUID курсора и переполнения offset не успела попасть в действующий API.
При возобновлении установленный исходник сравнен с локальным, существующий образ
проверен по digest и исходникам. Завершение этого кандидата не требует новой
сборки клиентов или повторной проверки неизменённых денежных правил/миграций.

Продолжение завершено 14 октября: сохранённый API-кандидат опубликован, итоговый
watchdog в 16:27 МСК без предупреждений. Перед публикацией сверены digest образа,

Linux-теста прошли. Под общей блокировкой сделаны свежий backup БД и исходников,
сохранены диагностические логи, заменён только API. Проверки публичных клиентов,
авторизации и отключённого Web прошли. Docker API healthy; пять типов счетов
не имеют расхождений с ledger. Временных БД и каталогов кандидата не осталось.
Некорректные UUID курсора и переполнение offset теперь защищены в действующем API.

Первая страница истории: до 426–591 мс, после 303–643 мс. Эта серия не доказывает
ускорение первой страницы. На позиции после 1 000 записей старый путь занимал
