# Правила версионирования Casper Loto

[English](VERSIONING.md) · **Русский**

Владелец утвердил эти правила проекта 23 октября 2026 года.
Текущая единая публичная версия — **Casper Loto 1.70.0**; её источник —
файл [`VERSION`](../VERSION). API, Mini App и Admin сохраняют самостоятельные
внутренние версии. Их соответствие общей версии записано в
[описании исходного выпуска 1.70.0](releases/1.70.0.md).

## Semantic Versioning

Публичная версия имеет формат **MAJOR.MINOR.PATCH** по принципам
[Semantic Versioning](https://semver.org/).

| Часть | Когда увеличивается | Пример |
| --- | --- | --- |
| MAJOR | Выпуск нарушает совместимость ранее поддерживаемых публичных контрактов приложения | `1.70.3 → 2.0.0` |
| MINOR | Выпуск добавляет совместимые функции: игру, задания, рейтинги, коллекции | `1.70.3 → 1.71.0` |
| PATCH | Выпуск исправляет ошибки без нарушения совместимости и добавления новых функций | `1.70.0 → 1.70.1` |

При увеличении MAJOR значения MINOR и PATCH сбрасываются до нуля.
При увеличении MINOR значение PATCH сбрасывается до нуля.
Количество функций, время разработки и масштаб визуального обновления
сами по себе не требуют повышения MAJOR.

От текущей исходной версии следующее совместимое функциональное обновление —
**1.71.0**, обновление только с исправлениями — **1.70.1**. Это альтернативные
следующие выпуски, а не уже состоявшиеся публикации. Далее отсчёт идёт от
последнего опубликованного публичного выпуска: например, исправление после
1.71.0 получит номер 1.71.1.

## Выпуски и журналы

1. Публичная версия повышается при фактическом выпуске изменений для игроков,
   а не при каждом коммите.
2. Несколько связанных мелких исправлений могут объединяться в один PATCH-выпуск.
3. Локальная разработка, тестирование, изменения документации и подготовка GitHub
   сами по себе не повышают публичную версию.
4. `CHANGELOG.md` не имеет собственной версии. Согласно
   [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), он описывает общие
   публичные выпуски Casper Loto под их номерами. Русский вариант использует
   те же обозначения выпусков и даты.
5. Для изменений, ещё не опубликованных игрокам, используется `[Unreleased]`.
   Завершённая редакционная работа и подготовка репозитория записываются
   в датированные заметки о разработке.
6. `DEVLOG.md` не имеет собственной версии. Записи имеют даты и темы;
   исторические DEV-номера сохраняются в архиве.
7. Технические версии API, Mini App и Admin ведутся отдельно; их соответствие
   каждому публичному выпуску сохраняется в технической документации.
   Эти номера не обязаны совпадать с публичной версией продукта.
8. Исторические номера, записи, снимки выпусков и существующие теги сохраняются.
   Исходные Changelog и Devlog остаются в [архиве истории](history/README.ru.md).
   Прежние заголовки с номерами компонентов ниже исходного выпуска 1.70.0
   являются историческими записями.
9. Перед выпуском агент определяет тип изменений и выбирает соответствующую
   публичную версию. MINOR и PATCH можно назначать и публиковать без отдельного
   согласования номера. Прямое согласование владельца требуется только перед
   увеличением MAJOR — первой цифры, например `1.x.x → 2.0.0`.
   Владелец уточнил это правило 23 октября 2026 года. Обычные правила проверок,
   резервного копирования, публикации и проверки сервера сохраняются.
10. Для открытия исходников GitHub Release и тег необязательны. Их создание —
    отдельное действие по оформлению выпуска; оно не является причиной повышать
    версию и не меняет манифесты прошлых публикаций.

## Исходная единая публичная версия

История начинается с 0.1.0 от 14 августа 2026 года; стабильная 1.0.0 состоялась
1 сентября 2026 года. Единая публичная 1.70.0 продолжает эту историю.
Проект не начинает отсчёт с 1.0.0 повторно, прежние выпуски не переименовываются.

Владелец прямо утвердил эту исходную версию. Производственный снимок и версии
пакетов сохраняются; согласуются публичное обозначение и документация.
Доступность GitHub владелец меняет отдельно после просмотра результата.
