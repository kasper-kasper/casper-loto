# Casper Loto 1.71.0

Compatible feature release prepared on 23 October 2026 at the owner's request.
Separate owner approval now applies only to MAJOR version increases.

| Component | Version |
| --- | --- |
| Public product | 1.71.0 |
| API and bot runtime | 1.60.0 |
| Mini App | 1.71.0 |
| Admin | 1.61.2 (unchanged) |

Achievement popups and inbox actions open the exact achievement in its category,
including items beyond the first page. Details open immediately; closing details
leaves the selected card highlighted. A persisted profile switch controls achievement
popups independently of Telegram delivery. Re-enabling does not replay a silent
backlog; inbox history and rewards remain intact.

Migration `0068_in_app_notifications` adds the enabled preference (default true)
and a nullable UTC re-enable boundary. Existing clients that omit the new setting
preserve its value. No money, draw, reward or catalog rules change; the achievement
launch epoch is preserved. The previously published automatic-purchase and purchase
notification fixes from 1.70.1 and 1.70.2 remain in the production source snapshot.

## Verification and publication plan

- Targeted achievement UI tests and PostgreSQL preference/navigation regressions;
  Mini App lint/typecheck, clean locked-dependency build and mobile browser smoke.
- No full project suite, financial scenario suite or broad bootstrap tests: the
  owner explicitly requests only checks necessary for this change.
- Before production migration, verify the additive migration against the current
  production schema and existing preference rows in a disposable database on VPS.
- Hold `/run/lock/k-loto-operations.lock` throughout baseline verification, VPS
  backups, upload, build, migration, restarts and health checks. Preserve API/bot
  diagnostic logs before replacing them; publish API/bot and gateway together.
- Keep all production database backups on VPS. Reuse the validated Admin artifact;
  no unrelated service or data cleanup.
- Verify HTTPS, exact client hashes, API health, schema head and preference defaults.

The public feature branch remains separate from previously local-only Git work.
This isolated production snapshot preserves those already published changes without
pushing their history as part of this task. Publication results are appended only
after verification.

## Production result — 23 October 2026

Published and verified from isolated source commit `d919d006`. API/bot 1.60.0,
Mini App 1.71.0 and public product 1.71.0 are live; Admin 1.61.2 is preserved.
VPS database/source backups and rollback images were created under the shared
operations lock, and API/bot logs were archived before replacement.

The scoped migration check passed on the current production schema and existing
preference rows in a disposable VPS database. Existing settings were unchanged;
new popup flags defaulted to true. Production reached schema
`0068_in_app_notifications`. HTTPS, exact client assets, authentication boundaries,
backup catalog, API health and independent monitoring passed with zero warnings.
Twelve deployed source hashes matched the candidate, including previous purchase
fixes. Achievement runtime and launch time `2026-10-20T23:00:01.857710+00:00`
are unchanged. No production test purchase or preference change was performed.

The first disposable import attempt encountered a pre-existing profile trigger
under pg_dump's empty search path. Only that disposable import was corrected by
disabling triggers while loading its two fixture tables; production triggers were
never disabled. The corrected scoped check passed before production migration.

The full project suite was not run, as explicitly requested by the owner.
Local evidence: `.tools/achievement-notification-release.log` and
`.tools/achievement-notification-production-verification.json`.
