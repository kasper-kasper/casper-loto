# Mini App: быстрый профиль

Выпуск API 1.56.4 / Mini App 1.66.5, 14 октября 2026.

Профиль читает готовую статистику за всё время из `player_profile_stats`:
количество билетов, активные/выигрышные билеты, расходы, выигрыши, лучший выигрыш
и непрочитанные уведомления. Баланс берётся из действующего денежного счёта.
Любимая лотерея выбирается из `player_lottery_stats` по числу невозвращённых
обычных билетов за всё время; прежний порядок при равенстве сохраняется.

Любимые числа считаются только по последним 1 000 невозвращённым билетам этой
лотереи, по `purchased_at DESC, id DESC`. Лимит применяется до раскрытия массива
чисел и подсчёта частот. Индекс обеспечивает выбор последних записей без
сортировки всей истории. Мгновенные игры не участвуют в выборе чисел.
Новой поясняющей надписи в профиле нет по просьбе владельца.

Открытие профиля выполняет до трёх SQL-запросов и не пересчитывает общие показатели
по истории. История Mini App загружается по 20 записей с существующей кнопкой
догрузки. Подробности открываются по запросу; купленные билеты не удаляются.
Навигация переиспользует профиль до 30 секунд и объединяет одновременные запросы.
Явное обновление после изменения данных получает новый ответ сервера.
Покупки меняют поколение состояния; устаревший ответ не заменяет новые данные.

## Согласованность и восстановление

Миграция 0056 один раз строит сводку по сохранённым данным. PostgreSQL-триггеры
на уровне SQL-операции обновляют только производные показатели внутри транзакции
источника: покупка, расчёт, возврат, мгновенный билет, чтение уведомлений.
Откат транзакции откатывает и сводку; повтор без новой строки не увеличивает её.
Правила покупки, выигрыша и движения CAS остаются в сервисах приложения.

`python -m scripts.check_player_profiles` выполняет только проверку соответствия
истории. `python -m scripts.check_player_profiles --rebuild` явно восстанавливает
производные таблицы, временно блокируя записи источников; использовать отдельную
транзакцию READ COMMITTED. Билеты, тиражи, балансы и ledger этот механизм не меняет.
Перестроение не выполняется при обычном открытии профиля.

Проверки и реальные замеры публикации фиксируются в DEVLOG.md. Изменение не
обещает постоянную задержку при любой нагрузке; сеть Telegram и другие экраны
имеют собственные расходы. Админка и SSE в этом выпуске не перерабатываются.
