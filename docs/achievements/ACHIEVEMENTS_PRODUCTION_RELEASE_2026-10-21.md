## Граница и восстановление

Срок хранится в PostgreSQL, переживает рестарт API и ноутбука. Фоновый job
проверяет одну запись каждые две секунды. При наступлении срока берёт общий
advisory lock достижений и короткий барьер записи исходных таблиц (NOWAIT,
SQL до пяти секунд), фиксирует фактическое UTC-время запуска и
базовые балансы в проекции. Balance и ledger не меняются. В штатном состоянии
не требуется закрывать миниапп на несколько часов. Если транзакция не может
завершиться, она откатывается и повторяется очередным job без частичного старта.
Занятая игровая операция не заставляет включение удерживать частично взятые
табличные блокировки: NOWAIT немедленно уступает и переносит попытку на другой такт.

Изменившаяся после подготовки версия каталога блокирует запуск. Уже начатая
система не может быть запущена повторно/обнулена. Если время пропущено до
подготовки, команда запрещает заднюю дату: не включать непроверенную систему.

Управление внутри production-контейнера API:

- `production-status --confirm-production` — время/состояние/очередь/ошибки.
- `production-cancel --confirm-production` — отмена только до начала учёта.
- `production-pause --confirm-production` — пауза выдачи/обработки с сохранением
  новых подтверждённых игровых событий.
- `production-resume --confirm-production` — продолжение сохранённой очереди.

Все команды — под `python -m scripts.achievements`. Старые локальные команды
сохраняют прежний запрет на production. Никакого API начисления/включения для
клиента не добавлено. Кейсы остаются planned, временно скрыты в интерфейсе.

Мониторинг раз в минуту читает только незавершённую очередь: готовые задания,
возраст ожидания, восемь исчерпанных попыток. Отдельные предупреждения —
непроизошедший спустя минуту запуск и задержка готовой очереди свыше пяти минут.
