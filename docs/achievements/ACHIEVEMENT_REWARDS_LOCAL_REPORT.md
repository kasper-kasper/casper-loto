## Выдача и деньги

CAS переводятся из Kasper Fund на баланс двумя проводками с одним идентификатором
операции части награды. Новая эмиссия для этого не создаётся. При недостатке фонда
награда сохраняется в ожидании, без частичного списания или отрицательного фонда.
«А так можно было?!» получает событие после успешной выплаты CAS за другое
достижение; собственная выплата не создаёт рекурсию.

Билет создаётся существующим сервисом покупки, с серверной ссылкой на часть
награды. Полная стоимость по снимку тиража оплачивается фондом; существующая
формула вклада в джекпот и сжигания сохранена. Для 3 333 CAS это 1 667 CAS
в джекпот и 1 666 CAS сжигания. Стоимость для игрока — ноль, источник — GIFT.
В расчёте выигрыша используется номинальная цена из снимка тиража. Участие,
обычные призы и главный выигрыш считаются тем же механизмом розыгрыша.

Разрешены только september/grob/pll/khan/pss. Выбирается ближайший открытый
тираж с доступным лимитом участия. Комбинация генерируется серверным безопасным
генератором по версии правил тиража. Подарочный билет занимает обычное место
в лимите участия и сохраняет обычную нумерацию.

Источник GIFT, нулевая оплата игроком и уникальная ссылка на часть награды
защищены ограничениями БД и неизменяемостью происхождения. Клиент не передаёт
эти параметры через API покупки. Подарки исключены из платных счётчиков и
платных выигрышей этой партии. Общие выигрыши профиля и реальный баланс
продолжают включать их выплаты.

Каждая платёжная часть обрабатывается отдельной транзакцией: ошибка билета
не отменяет уже выплаченные CAS. Временно недоступная выдача получает статус
waiting и следующую попытку через пять минут. Проверяются максимум 20 готовых
частей за проход по частичному индексу. Ожидающая выдача не блокирует игровые
события пользователя; ошибок доставки нет в пути покупки или открытия экрана.
Технические сбои сохраняют существующие ограниченные повторы и диагностику.

Кейс хранится исключительно как `type=case, amount=1, planned=true`. Часть
награды имеет статус planned, без даты выдачи и без попыток обработки. Предметы,
инвентарь, открытие, содержимое и вероятности кейсов не реализованы. Их будущая
выдача по уже сохранённым основаниям потребует отдельного согласованного этапа.

## Интерфейс

На карточке и внутри подарочного билета — маленькая контурная иконка подарка
и подпись «Подарочный». В подробностях: «Награда за достижение» и
«С баланса ничего не списано». Билеты остаются в обычном разделе «Мои билеты».

Карточки и уведомления показывают состав награды: CAS, конкретную лотерею,
«1 кейс · позже». В подробностях объяснено, что выдача кейса подключится после
запуска системы кейсов. Конечные обновления по событию достижения освежают баланс
и прогресс; непрерывный опрос достижений не добавлен.

  время отложенной доставки; старые снимки и финансовая история не изменяются.

- `achievements.py`: финансирование, доставка по частям, очередь ожидания.

- API уведомлений: фактический статус доставки без дополнительных запросов.
- `AchievementRewards.tsx`, `GiftTicketBadge.tsx`, карточки/подробности билета,
  достижения и уведомления; стили в `achievements.css` и `account.css`.
- Тесты CAS/билетов/очереди/интерфейса; локальные команды и документация.

Предыдущие неоценённые получения остаются неизменными. Автоматическая выплата
старых снимков не выполняется. Для просмотра новых наград локальный ярлык
использует отдельный тестовый профиль; прежний профиль и его история сохранены.
Резервные копии обеих локальных БД перед миграцией находятся в `.tools`.

Перед production остаются отдельная публикация/активация и проверка запаса фонда.
Официальное начало учёта не устанавливается этим локальным этапом.
