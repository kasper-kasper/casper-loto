# 11 легендарных достижений и коллекция — локально, 20 октября 2026

Добавлены десять утверждённых джекпотных достижений и финальное **«Каспер,
подвинься»**. Общий локальный каталог: **93 достижения** — 22 обычных,
23 необычных, 20 редких, 17 эпических и 11 легендарных. Действующие условия
и суммы прежних категорий не изменены, дата запуска и история получений сохранены.

## Награды и учёт

Полная таблица находится в `ACHIEVEMENTS_LEGENDARY_REWARDS.md`; машинный каталог
— `achievements.legendary.catalog.json`. Для исходных десяти: 40–350 млн CAS,
100–500 билетов своей игры и 20–100 будущих обычных кейсов. Итог финала:
**1 млрд CAS, по 300 билетов каждой из десяти игр, 200 будущих обычных кейсов,
особый значок и тема «За гранью»**. Никаких легендарных кейсов не создаётся.

Общий объём категории с финалом — 2,13 млрд CAS, 5 825 билетов/карточек и
765 будущих кейсов. Это конфигурация разовых наград, не немедленная выдача всей
категории всем игрокам. Стоимость билетов не включена в сумму CAS. Устойчивость
массовой выдачи для экономики в этой задаче не оценивалась.

Только окончательные оплаченные билеты с положительной выплатой настоящего
джекпота, с исходного старта системы. Старые форматы не подменяют новые: CODE —
ровно пять правильных позиций, PULSE — оба поля и шифр, Ball — 5+1, Grand — 5+2,
Bingo — все 12 до 28-го хода, без технического распределения. Dual исключён.
Финал считает фиксированный набор десяти ID; сам себя не считает, новые легенды
его порог не увеличат. Импорт проверяет неизвестные зависимости и циклы.

CAS и номинал билетов оплачивает существующий фонд через immutable ledger.
Размер джекпота, таблицы выплат, генерация, цены и правила покупок не менялись.
При недостатке фонда награда остаётся в ожидании; получение достижения сохраняется.
Изменение наград позднее требует новой версии каталога и действует на будущие
получения. Ранее выданные снимки и выплаты не переписываются.

## Компактные пакеты билетов

Новый тип `ticket_pack` хранит до 500 билетов одной записью награды. У финала
14 корневых частей: CAS, два косметических открытия, десять пакетов и кейсы.
По мере выдачи создаётся отдельная неизменяемая дочерняя часть для каждого
настоящего билета. Связь билета с частью остаётся уникальной.

- Одна выдача билета за транзакцию через штатный purchase service, включая
  FAST, CODE и PULSE. Пакет не добавляет массовый синхронный цикл в покупку игрока.
- Детерминированные ID дочерних частей и счётчик `completed_units` изменяются
  в той же транзакции под блокировкой получения. Повтор и параллельные запросы
  не превышают утверждённое количество.
- Очередь уступает управление между порциями. Ожидающий остаток получает новый
  номер события, а не удерживает игровое событие игрока на всю выдачу 3 000 билетов.
- Продолжение читает максимум 16 корневых позиций по существующему уникальному
  индексу `(award_id, position)`; позиции дочерних частей начинаются с 16.
  Уже выданные тысячи частей повторно не загружаются.
- Учитываются купленные игроком билеты, текущий лимит на тираж, закрытие продаж,
  фонд и доступный пул Bingo. Заполненный тираж пропускается; остаток ждёт
  следующих подходящих тиражей той же игры. Сезонная игра не заменяется другой.
- Дополнительно подарки не покупают всё пространство комбинаций; у Bingo
  сохраняется свободное место в конечном пуле. Уменьшать пакеты по 300 не нужно:
  наименьшее пространство среди этих игр — 1 365 комбинаций «2:22».

С текущими локальными лимитами финальные 300 билетов требуют минимум четыре
тиража Bingo, по три «2:22»/September/Halloween, по одному остальных игр, если
лимиты свободны. Реальная выдача может занять больше тиражей. Кейсы записаны
одной planned-частью с количеством; их инвентарь и открытие отложены.

## Коллекция и оформление

В профиле добавлен раздел **«Коллекция»** с вкладками значков и тем. Сервер хранит
постоянные открытия, дату и источник, выбранный значок и выбранную тему.
Игрок может снять значок и вернуться к стандартному оформлению.

Золотая тема открывается один раз после первой легенды: конфликты повторных
открытий не меняют исходный источник и дату. Финал открывает отдельный значок
с официальным знаком Casper, платиновым кольцом и десятью золотыми точками,
а также статичную тему «За гранью». Темы применяются только по выбору игрока
к его профилю, общий интерфейс и чужие экраны не меняются.

Для значков использованы существующий официальный символ Casper и названия/
словесные знаки действующих игр; для Halloween повторно используется фирменный
компонент с силуэтом. Стандартные случайные пиктограммы не подменяют символику.
В коллекции доступны полноцветный предпросмотр значка и предпросмотр темы
без выдачи или активации заблокированной награды. У имени в профиле показывается
один выбранный компактный значок. Для будущих рейтингов/публичных списков добавлено
пакетное серверное представление `selected_badges` с пределом 200 пользователей
на запрос; самого раздела рейтингов в текущем клиенте нет, он не придумывался.

`GET/PUT /api/v1/miniapp/achievements/collection` используют текущую авторизацию.
Выбор проверяется application service и составными FK на открытия этого же
пользователя. Клиент не может открыть предмет, выбрать чужой/закрытый предмет
или передать CAS в API выбора. Чтения не начисляют награды. Коллекция загружается
при открытии раздела/профиля, непрерывный опрос не добавлен.

## Миграция и файлы

**0064_legendary_collections** добавляет parent/cursor-поля наград и две sparse
таблицы: `collection_unlocks`, `collection_preferences`. Старые награды сохраняют
нулевой счётчик, provenance и ограничения уникальности билетов остаются.
Открытия защищены от изменения/удаления; прогресс пакета может только увеличиваться.
Миграция проверена на preview/test/fresh, Alembic check не находит новых операций.

Основные файлы:

- `application/legendary_achievements.py`, `domain/achievements.py` — каталог,
  фиксированное множество получений, ограниченные пакеты и количества кейсов.
- `application/achievement_catalog.py`, `achievements.py`, `achievement_packs.py`,
  `domain/achievement_gifts.py` — зависимости, управление инициализацией,
  событийная выдача, лимиты, защита от полного покрытия.
- `application/collection.py`, `api/routes/achievements.py`,
  `infrastructure/database/achievement_models.py`, миграция 0064.
- `application/weekly.py` — добавлены только три FAST ID в уже существующий
  серверный whitelist подарков; финансовые и игровые правила сохранены.
- `scripts/achievements.py legendary-catalog`, `scripts/local_preview_setup.py`.
- Mini App: `Collection.tsx`, `collectionTypes.ts`, `collectionGames.ts`,
  `useProfileCosmetics.ts`, `LegendaryBadge.tsx`, `collection.css`; интеграция
  в `AccountHub`, `App`, API, общие карточки достижений и отображение наград.
- Тесты `test_legendary_achievements.py`, `Collection.test.tsx`; актуализирована
  граница будущих кейсов в epic-тесте. Старый тест компилятора публикаций читает
  перенесённую локальную библиотеку из архива и пропускается, если приватного
  архива в чистом клоне нет. Функция публикаций не включалась.
