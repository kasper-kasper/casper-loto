# Версии, Changelog и Devlog

[English](HISTORY_GUIDE.md) · **Русский**

## Три разные вещи

| Что | Что означает | Пример |
| --- | --- | --- |
| Версия приложения | Обозначает выпущенное состояние программы | Mini App `1.70.0` |
| Запись Changelog | Описывает заметные изменения выпуска с его же номером | Что изменилось в Mini App `1.70.0` |
| Запись Devlog | Рассказывает о работе и решениях; имеет дату и название | «Английский интерфейс», 23 октября 2026 |

У Changelog нет собственного счётчика версий. Запись Devlog не создаёт новую
версию приложения. Коммит фиксирует изменение в Git и не обязан становиться
отдельным выпуском или заметкой. GitHub Release оформляет состояние, отмеченное
тегом, с описанием выпуска; его не требуется создавать для каждого коммита.

## Сейчас нумерация сохранена

На момент проверки 23 октября 2026 в исходниках указаны:

| Компонент | Существующая версия |
| --- | --- |
| API / Python-пакет | `1.59.0` |
| Mini App | `1.70.0` |
| Admin | `1.61.2` |

Владелец попросил отложить решение о нумерации. Редакционная работа не меняет
манифесты пакетов, lockfiles, версии в работающем приложении, теги и прежние
выпуски. Новый общий номер проекта не назначен. Единый будущий номер
или сохранение отдельных версий компонентов будут решаться отдельно.

## Как упорядочена история

- Связанные мелкие исправления объединены в сводки. Диапазон в старом заголовке
  перечисляет существующие выпуски и не создаёт заменяющую их версию.
- Исходные номера и даты сохранены в полных исторических записях.
- Локальные эксперименты и предложения остаются историей разработки.
  Выпущенными возможностями они описываются при наличии подтверждения публикации.
- У публичных Changelog и Devlog есть английская и русская версии.
  Старые технические записи сохранены в архиве на исходных языках.
- Дата реализации отличается от даты публикации. Например, работа над английским
  Mini App записана 22 октября, публикация проверена 23 октября.

В [архиве истории](history/README.ru.md) лежат побайтовые снимки обоих исходных
журналов, хэши и указатель заголовков. Корневые имена журналов и формат заголовков
в квадратных скобках сохранены для чтения админкой. На VPS эта документация
попадёт со следующей обычной публикацией приложения; пересборка работающей игры
ради редактирования журналов не требуется.

## Принятые подходы и примеры

[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) — распространённая
рекомендация: отбирать значимые изменения, использовать раздел Unreleased,
даты и заголовки выпусков. Каждая правка кода не обязана становиться выпуском.

[Semantic Versioning](https://semver.org/) определяет смысл `MAJOR.MINOR.PATCH`
через совместимость объявленного публичного API: несовместимые изменения,
совместимые новые возможности и совместимые исправления. Этот подход не задаёт
собственную версию документа Changelog или конкретный следующий номер проекта.

Для сравнения: [заметки VS Code](https://code.visualstudio.com/updates)
собраны по выпускам продукта, а в [блоге React](https://react.dev/blog)
есть датированные объявления и статьи о разработке.
[GitHub Releases](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)
основаны на тегах Git. Это разные способы рассказывать об истории проекта.
